# Command Frames

A command list declares which custom commands the device accepts, Command Ack reports the outcome of those commands (see [Commands](../commands)). `CommandFlags` bits 5–6 carry the Home Assistant entity category, so a device setting can be marked as such without a trailing field. See
[Elements](../elements) for field details.

When `CommandFlags` bit 3 is set, `StateSignal` is followed by a one-byte `StateSource`: `0` a
signal, `1` a state channel.

Bit 0 says a range was declared, not that the entry is a number. A number command whose device
declared no range leaves the bit clear and omits `RangeMin` and `RangeMax`
altogether; it accepts any value its handler will take, and never answers
[`OUT_OF_RANGE`](../status-codes). A host builds the control from its own defaults in that case.
It must not read absent limits as `0` to `0` — a window nothing but zero fits through.

`RangeStep` has a bit of its own, bit 7, and is not part of that range. A step is display
resolution: nothing is rounded to it and no value is refused for falling between two of them. So
the two are declared independently — a command may state limits without a resolution, a
resolution without limits, both, or neither. Because it is flagged rather than sent as a
sentinel, an absent step is simply absent; there is no `0` a host has to know to read as "none".
Optional fields follow in bit order, which is why the step trails the text length rather than
sitting beside the min and max.

A host may have a floor of its own — Home Assistant refuses a step below `0.001` — and is
expected to drop that one control rather than quietly coarsen what the device asked for.

`CommandPayloadMax` repeats on every entry and is the same on all of them: one receive buffer
serves the device. A host derives what a given command leaves for its parameters by subtracting
the name and the separating comma, and compares that against the value it is about to send —
encoded, since encoding happens before the frame is built.

`CmdHash` covers the bytes the device received, so it matches only when those are the bytes the
sender wrote. `CmdNameHash` covers the name alone, which sits before the first comma and so
survives a frame the device could not take in full.

| CmdHash | CmdNameHash | Meaning |
|---------|-------------|---------|
| match | match | Acknowledged command received intact |
| no match | match | Same command, different bytes: it did not arrive as sent |
| no match | no match | Not a command this sender issued |
